# STT 추가 학습 계획 (TeamUNIVA Qwen3-ASR 한국어판)

2026-11-17 작성. 사용자 결정은 다음과 같다.
- 원래 Qwen3-ASR-1.7B는 지웠다. 선택지, 모델 파일, `ASR_MODEL_ID`, 그 모델 전용 서버 힌트 42개가 모두 대상이다.
- 오늘 저녁 STT 학습을 먼저 하고, TTS(H2-D) 학습은 내일 저녁으로 미룬다.
- 학습은 사용자가 '시작해'라고 할 때만 건다.

## 1. 출발점

- **시작 모델:** `TeamUNIVA/qwen3_asr_1.7b_ko`(Apache-2.0)를 `server/.models/qwen3_asr_1.7b_ko`에 둔다.
- **UNIVA가 만든 방식:** 모델 카드에 따르면 [ms-swift](https://github.com/modelscope/ms-swift)로 전체 파라미터를 4단계로 학습했다. SFT, GSPO(강화학습), SFT, GSPO 순서다. 우리는 이 길을 그대로 따라 **ms-swift**를 쓰고, 맥 16GB에서는 **LoRA**만 쓴다.
- **ms-swift 지원:** 4.6.1이 `qwen3_asr` 모델과 템플릿을 갖고 있다. 요구 사항은 `qwen-asr`, `transformers==4.57.6`이다.
- **Qwen 공식 학습 코드:** 설치된 `qwen-asr` 패키지에는 학습 코드가 없다. 공식 예제는 아직 직접 보지 않았다.

## 2. 기준선

| 시험 | 결과 |
|---|---|
| 11/13 녹음 33개, 원래 Qwen + 힌트 42 | CER 10.3%, 핵심어 69/71, 0.99초 |
| 11/13 녹음 33개, UNIVA 힌트 없음 | CER 9.8%, 핵심어 67/71, 0.71초 |
| 11/17 15:08 폰 시험, UNIVA + ElevenLabs | 인식 88%, ○ 96/102 |

- **주의 1:** 위 CER은 *실제로 말한 문장*이 아니라 **시험표 대본(say)** 을 기준으로 잰 값이다. 저장본의 spoken 칸이 비어 있다. 그래서 CER의 대부분은 사용자가 대본과 다르게 말한 입말 차이다.
- **주의 2:** 학습 효과를 제대로 보려면 평가 녹음의 정답을 사람이 들어 보고 확인해야 한다(아래 3-1).
- **주의 3:** 33개는 작은 표본이다.

### 힌트를 쓰지 않는 이유 (2026-11-17 사용자 결정)

| UNIVA, 11/13 녹음 33개 | CER | 핵심어 |
|---|---|---|
| 힌트 없음 | 0.098 | 67/71 |
| 힌트 42개 | 0.104 | 69/71 |

- **힌트가 고친 것:** D7 '사업비'가 '생활비'로 맞게 나왔다(뜻이 바뀌는 차이). C3는 '부루펜'이 '부르펜'이 됐다(표기 차이).
- **그래도 뺀 이유:**
  - 전체 CER이 조금 나빠졌다.
  - 원래 모델에서 힌트 글을 그대로 받아 적은 사고가 있었다(11/12 D19).
  - 힌트 낱말을 시험표에서 뽑아 시험 점수가 실제보다 좋게 나온다.
- **결정:** 서버 힌트 없이 두고, 이런 낱말은 **학습으로 익히게 한다.** 학습 문장에 '생활비'와 '부르펜' 문장을 넣었다. 학습 뒤에는 D7과 C3을 따로 확인한다.

## 3. 데이터

### 3-1. 평가 세트 (학습에 쓰지 않는다)

- **만드는 법:** `cd server && .venv-asr/bin/python -m finetune.build_dataset eval`
- **녹음:** 실기기 시험 녹음 76개다(11/13 두 번, 11/17 한 번). 처음에 87개로 셌는데, 같은 녹음 11개가 두 번 저장돼 있어 md5로 한 번씩만 남겼다.
- **정답:** 시험표 spoken 칸이 있으면 그것, 없으면 대본을 쓴다. 대본을 쓴 줄은 `verified=false`다. 지금은 76개 모두 false다.
- **사람 확인:** `server/.train/stt-ko/data/eval_check.csv`의 마지막 칸에 실제로 말한 문장을 적으면 정확한 평가가 된다. 스크립트가 이 칸을 다시 읽는 기능은 아직 없다. 채우면 붙인다.
- **시험표 문장(C·D·E):** 평가용으로만 남긴다.

### 3-2. 학습 문장

- **파일:** `server/finetune/train_sentences.txt`에 684문장, 9,946자를 담았다.
  - 앞 200개는 가족 비서 말이다(일정, 아이, 장보기, 병원·약, 돈, 집안일, 부탁, 가족 행사, 반려견, 서류, 날짜·숫자, 부정·고치기, 짧은 말).
  - 나머지 484개는 사용자가 요청한(11/17) 시험표 밖의 다양한 일상 말이다. 날씨, 교통, 음식 주문, 요리, 쇼핑, 은행, 병원, 학교, 직장, 전화, 집, 여가, 감정, 숫자·주소, 기기 조작, 긴 말, 존댓말·민원, 어린이 말, 어르신 말, 운동·취미, 동물, 뉴스, 외래어·브랜드, 이사를 담았다.
- **숫자는 적는 꼴로 통일한다:** `8만 4천 원`, `11시 30분`, `12월 3일`, `2개`. 한국어판은 같은 숫자를 '팔만 사천 원'으로도, '84000원'으로도 적는다. 학습 정답을 한 가지 꼴로 맞춰 둔다.
- **TTS가 읽는 글:** 서버 `normalize_for_speech`로 입말로 바꾼다. 바꿈이 틀리는 줄은 `적는 글 | 읽는 글`로 따로 적었다(예: `3번`→세 번, `04001`→공사공공일, `KTX`→케이티엑스). 테스트로 읽는 글에 숫자나 영문이 남지 않는지 확인한다.
- **겹침 확인:** 시험표 문장과 글자 차이가 35%보다 작으면 거의 같은 문장으로 보고 막는다(`finetune.build_dataset check`). 지금 겹치는 문장은 0개다.
- **낱말은 겹쳐도 된다:** 시험표 낱말(부르펜, 생활비 등)은 일부러 넣었다. 그래서 평가 점수가 실제보다 좋게 나올 수 있다.

### 3-3. 학습 소리 (2026-11-17 결정: 맥 Qwen3-TTS)

- **ElevenLabs는 쓰지 않는다:** ElevenLabs [금지 사용 정책](https://elevenlabs.io/use-policy) 12항(2026-10-09)이 생성한 소리로 AI 모델을 학습하거나 학습 데이터셋에 넣는 것을 금지한다.
- **맥 `say` 목소리도 쓰지 않는다:** 맥 사용권에서 개인·비상업 용도로 제한되는 것으로 알고 있다(확인 필요).
- **쓰는 것:** 맥 llama.cpp **Qwen3-TTS 1.7B Base Q8**(Apache-2.0)였다(`server/finetune/make_tts_audio.py`, 11/18 사용자 결정으로 맥 Qwen3-TTS 모델과 함께 지움).
  - 목소리는 서버 견본 g, h2-d, h2를 문장마다 돌려 쓰고 seed도 문장마다 바꾼다. 세 견본은 모두 107이 설명으로 만든 목소리이고 실제 사람이 아니다.
  - 남자 목소리 견본은 없다. 필요하면 107의 목소리 설계(VoiceDesign)로 만들 수 있지만, 107은 먼저 묻는다.
  - 한 문장에 약 6~7초가 걸려 684문장이면 약 1시간 15분이다.
- **직접 녹음도 쓸 수 있다:** 녹음 파일을 `<문장 번호>_<이름>.wav`로 두면 된다. 가족 음성은 동의를 먼저 받는다.

## 5. 맥에서 되는지 (2026-11-17 작은 시험)

**가져오기(2026-11-19~, 와치 API 연결됨)**
- 와치 '🎤 음성 모으기' 내보내기: `GET https://pw-api.uptive-korea.com/api/v1/stt-collect/export`(헤더 `X-Stt-Key`, 키는 맥 키체인 `stt-collect-key` 또는 환경변수 `STT_COLLECT_KEY`). zip = `manifest.jsonl` + `audio/SPKxx/<clip_id>.wav`(16kHz 모노 16bit).

- 학습 세트: `python -m finetune.build_dataset collect <푼 폴더>…` → `train.jsonl`. 정답은 manifest의 `transcript`. 빼는 것: `finetune/collect_exclude.txt`(11/19 SPK01 P048·P049·P099 — 안내 문장을 그대로 읽음), 같은 녹음, 정답이 시험표와 거의 같은 것.
