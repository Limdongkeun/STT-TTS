# 단계별 시험 계획

한 단계씩 확인하고 넘어간다. 각 단계 결과는 `results/` 에 날짜별로 남긴다.

| 단계 | STT | 답 찾기 | TTS | 확인할 것 |
|---|---|---|---|---|
| 1 | 없음(글로 묻기) | 고정 답 | mock | 앱 ↔ 서버 연결, 화면 흐름 |
| 2 | 폰 기본 STT | 고정 답 | mock | 한국어 인식, 가족 호칭 인식 |
| 3 | 폰 기본 STT | 고정 답 | **Qwen3-TTS Sohee** | 발음·자연스러움·속도 |
| 4 | **서버 Qwen3-ASR** | 고정 답 | Qwen3-TTS Sohee | 폰 STT 와 정확도·속도 비교 |
| 5 | 고른 STT | **기존 LLM·DB** | Qwen3-TTS Sohee | 실제 답으로 전체 흐름 |
| 6 (나중) | + VAD·문장 단위 읽기 | | | 버튼 없이 끝내기, 첫 소리까지 시간 |

## 1단계 — 연결 확인 (모델 없음)

1. 서버 ① mock 으로 실행 (`README.md`). 고정 답으로 하려면 `ANSWER_PROVIDER=fixed`를 붙인다(2026-11-05부터 기본은 `family-demo`).
2. 앱 `.env` 두 주소를 모두 `http://<맥미니 IP>:8002` 로
3. 앱에서 "글로 바로 묻기" → 고정 답이 보이고 '삐' 소리가 나면 통과

## 2단계 — 폰 기본 STT

- `docs/test-sentences.md` 의 **A. 질문 문장**을 소리 내어 읽는다.
- 기록: 문장마다 맞게 받아 적었는지, 틀린 단어.
- 조용한 곳 / 시끄러운 곳 / 천천히 말하기(부모님 말투) 각각 해 본다.

## 3단계 — Qwen3-TTS (Sohee)

- 서버 ② 실행. 첫 요청은 모델을 받느라 오래 걸린다(그 시간은 기록에서 뺀다).
- `docs/test-sentences.md` 의 **B. 답 문장**을 "글로 바로 묻기" 대신 `/tts` 로 직접 넣어도 된다:
  `curl -s -X POST http://localhost:8002/tts -H 'Content-Type: application/json' -d '{"text":"...","normalize":true}'`
- 1.7B 와 0.6B 를 같은 문장으로 비교.

| 잴 것 | 방법 |
|---|---|
| 만드는 시간 | 응답의 `elapsedMs` |
| 실시간 배율(RTF) | `elapsedMs / 1000 / durationSec` — 1 보다 작아야 기다림 없이 읽을 수 있음 |
| 틀린 발음 | 문장마다 잘못 읽은 단어 수 |
| 자연스러움 | 1~5 점 (듣는 사람 2명 이상) |

## 4단계 — Qwen3-ASR (서버 STT)

- 서버 ③(8001) 과 ②(8002) 를 함께 띄우고, 앱 `.env` 의 STT 주소를 8001 로.
- 2단계와 **같은 문장**을 앱의 '서버 Qwen3-ASR' 모드로 말한다.
- 0.6B / 1.7B 비교. 글자 오류율(CER) = 틀린 글자 수 ÷ 전체 글자 수.
- 나중 전화 연결 대비: 8kHz 로 낮춘 음성도 시험한다
  `ffmpeg -i in.m4a -ar 8000 -ac 1 phone.wav` → `curl -F audio=@phone.wav http://localhost:8001/stt`

## 5단계 — 기존 LLM·DB 연결

- `server/app/answers.py` 에 실제 연결을 추가한다(키·주소는 환경변수).
- 답 글에 날짜는 "11/4" 대신 DB 날짜로 "11월 4일" 처럼 만든다(빗금 날짜는 읽기 변환이 바꾸지 않음).

## 6단계 — 나중에

- **VAD(Silero, MIT)**: 조용한 시간 0.8~1.2초에서 시작, 천천히 말하는 분은 1.5초 이상. 사용자별 설정값.
- **문장 단위 읽기**: LLM 이 스트리밍으로 답을 줄 때, 첫 문장부터 TTS. 첫 소리까지 시간을 잰다.

## 2단계 추가 시험 — 가족 돌봄 대화

서버 폴더에서 `uv run uvicorn app.main:app --host 0.0.0.0 --port 8002`로 실행한다(기본 답 모드가 `family-demo`다. 앱 맨 위에 "답: 가족 돌봄 시험(family-demo)"이 보이는지 확인한다). 기존 개발 빌드에서 Metro를 새로고침한다. 텍스트 입력으로 답을 먼저 확인하고, iOS와 Android에서 폰 기본 STT로 같은 문장을 말한다. 자동 대화는 대화 모드를 켠다.

| # | 말할 내용 | 기대 결과 |
|---|---|---|
| C1 | 다음 주 우리 집 일정 뭐야? | 화요일 가족 식사, 토요일 장보기 |
| C2 | 소윤이 이번 주 학교 학원 일정 뭐야? | 수요일 학교 체험학습, 금요일 피아노 학원 |
| C3 | 애기 해열제 부르펜 계열 먹었는데 시간 체크해줘 | 몇 시에 먹였나요? |
| C4 | 30분 전에 먹였어 | 서버의 한국 시각에서 30분을 뺀 값을 시험 기록에 반영. 가상 일정에 등록된 다음 예정 시각 오후 9시를 안내 |
| C5 | 아니, 30분 전이 아니라 한 시간 전이야 | 같은 시험 기록의 시간을 한 시간 전으로 수정 |
| C6 | 아버지 병원 예약 언제였지? | 등록일 11월 2일, 예약일 11월 12일 목요일 오전 10시를 구분해 답변 |
| C7 | 소윤이 다음 주 학교 학원 일정 뭐야? | 이번 주 일정으로 답하지 않고 시험 범위를 안내 |

C3 → C4 → C5는 같은 앱에서 이어서 말한다. 기록은 앱 세션의 가상 값이다. 오후 9시는 시험 데이터에 미리 등록된 값이다. 텍스트의 정확한 시간은 API 자동 테스트에서 오후 4시 기준으로 확인한다.

기기별로 모델과 OS 버전을 적고, 각 턴의 **인식한 말 / 핵심 정보 일치 여부 / 화면 답변 / 들린 답변**을 남긴다. mock TTS는 재생 확인용 삐 소리가 난다. 답변 문장을 실제로 들어보려면 같은 서버에 Qwen TTS를 켜서 반복한다.

|---|---|---|---|---|---|

## 2단계 추가 시험 — 부부 공유 업무 (D1~D25)

서버를 기본값으로 실행한다(`uv run uvicorn app.main:app --host 0.0.0.0 --port 8002`). 기록(장보기·부탁·당번 등)은 서버 메모리에 있어서, 같은 서버에 붙은 폰들이 함께 본다. 서버를 다시 켜거나 앱의 **시험 데이터 초기화**를 누르면 처음 시험 데이터로 돌아간다.

1. 앱에서 **시험 데이터 초기화**를 누른다.
2. 누가 했는지는 문장 속 남편·아내로 알아듣는다(앱에서 '나'를 고르지 않는다).
3. `docs/test-sentences.md`의 D1~D25를 위에서부터 차례로 말한다. 기대 답은 [스펙](../.scratch/family-shared-tasks/spec.md)에 있다.
4. D13 → D14 → D15로 부탁이 공유 기록에 남는지 본다(폰 두 대로 해도 같은 서버면 같이 보인다).
5. 각 턴마다 **인식한 말 / 핵심 정보(금액·날짜·이름) 일치 / 화면 답 / 들린 답**을 아래 표에 적는다. 답이 틀리면 서버 터미널의 `ask question=…` 줄도 같이 적는다.
6. 폰이 잘못 받아 적었는데 서버가 고쳐서 맞게 답했으면 서버 터미널에 `ask corrected …` 줄이 보인다. 고치지 못한 낱말(이름·약 이름·동의어)은 [스펙의 STT 보정 목록](../.scratch/family-shared-tasks/spec.md#stt-보정-serverappstt_correctionpy-2026-11-05-추가)에 더할 후보로 적는다.

시험 데이터의 날짜는 2026년 11월 기준이다(D9·D20·D22는 2026-11-05에 말한다고 보고 쓴 기대 답이다). 다른 날 시험하면 "내일", "남은 날" 답이 달라진다.

| 기기·OS | 문장 # | 나 | 인식한 말 | 핵심 정보 일치 | 화면 답 | 들린 답 |
|---|---|---|---|---|---|---|
| | | | | | | |

## 앱 시험표로 기록하기 (2026-11-05~)

앱 화면 맨 아래 **시험표**에서 C1~C7, D1~D25를 차례로 시험한다. 문장 목록과 기대 답은 서버(`GET /test-cases`, `server/app/test_sheet.py`)가 갖고 있다. 기록은 기기(예: `ios-27-0-1`, OS와 버전으로 자동)마다 묶인다.

1. 서버를 켜고 앱을 새로고침한다.
2. 앱 위쪽 **시험 데이터 초기화**를 누른다. 서버 시험 데이터와 시험표(○/×·인식한 말)가 함께 비워진다. 저장하지 않은 시험표가 있으면 "저장하고 초기화 / 저장하지 않고 초기화 / 취소"를 묻는다. 저장본은 지워지지 않는다.
3. 카드의 **🎤 이 문장 말하기**를 누르면 바로 듣기 시작한다(맨 위 STT 고르기에 따라 폰 기본 STT 또는 서버 STT). 카드 안에 받아 적는 글이 보인다. 다 말하면 쉬는 시간 뒤 저절로 끝나고, 다시 누르면 바로 끝난다.
4. 답이 나오면 **인식한 말**과 **화면 답**이 자동으로 적히고, 다음 문장으로 넘어간다. 시험표에는 말로 한 턴만 적힌다("글로 바로 묻기"는 인식 시험이 아니라 적지 않는다). 화면 답이 기대 답과 글자까지 같으면 "화면 답 ○"가 미리 채워진다(날짜에 따라 바뀌는 문장은 직접 누른다).
5. **핵심 정보**와 **들린 답**의 ○/×를 누르고, 틀린 낱말은 메모에 적는다. 누를 때마다 맥에 임시 저장돼서 앱을 새로고침해도 남는다. TTS가 mock('삐' 소리)이면 **들린 답**은 흐리게 보이고 끝낸 문장·비교에서 빠진다. 기본 TTS인 사전 녹음(prerecorded, D1~D25)에 그 답의 녹음이 없으면(C1~C7, 순서가 바뀌었거나 잘못 인식해 다른 답이 나온 경우, 11/5가 아닌 날의 D6·D9·D20·D22) 소리 없이 화면 답만 나오고 **들린 답**에 '녹음 없음'이 적힌다. '녹음 없음'은 끝낸 문장으로 센다. 음성을 받았는데 폰에서 2초 안에 재생이 시작되지 않으면 앱이 한 번 다시 틀고, 그래도 안 되면 화면에 알리고 그 문장 메모에 '재생 안 됨'을 적는다.
   - 카드마다 **인식 정확도**(= 1 − 글자 오류율 CER)가 자동으로 나온다. 말한 문장과 인식한 말을 띄어쓰기·문장부호 빼고 글자로 비교한다. 숫자와 한글 수("1시간" vs "한 시간")는 다른 글자로 센다. 저장본·`history.md`에는 평균이 남아 STT끼리 비교하는 기준 숫자가 된다.
6. 다 하면 **💾 저장하기**를 누른다. 지금 시험표가 **저장본**으로 남고(그때의 코드 버전: git 커밋, 수정 중인지), 이어서 시험표와 서버 시험 데이터가 **바로 처음으로 되돌아간다**. 저장이 실패하면 아무것도 지우지 않는다.
7. 코드를 고친 뒤 2~6을 다시 한다. 시험표 위쪽 **지난 저장본**에서 나아진 문장(×→○)과 나빠진 문장(○→×)을 본다.
8. 말로 한 턴마다 **어떤 STT로 받아 적었는지**(폰 기본 STT, 또는 서버 STT 모델 이름: `/health`의 `sttModel`)가 함께 적힌다. 저장본에는 STT 이름과 서버의 TTS 이름이 남고, **비교는 같은 STT의 바로 앞 저장본과만** 한다. 그래서 폰 기본 STT(이번 주)와 Qwen3-ASR(다음 주) 저장본이 섞이지 않는다. 두 STT의 결과는 `history.md`에서 나란히 본다.

맥에 남는 파일(`results/`는 git에 올리지 않는다):

| 파일 | 내용 |
|---|---|
| `results/test-runs/<기기>/draft.json` | 작성 중인 시험표 |
| `results/test-runs/<기기>/<저장 시각>.json`, `.md` | 저장본(코드 버전·요약·결과 표) |
| `results/test-runs/<기기>/history.md` | 저장본마다 한 줄: 시각, STT, TTS, 코드 버전, 인식 정확도(평균), 끝낸 수, ○ 수, × 있는 문장, 같은 STT 지난번보다 |
