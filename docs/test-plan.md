# 단계별 시험 계획

한 단계씩 확인하고 넘어간다. 각 단계 결과는 `results/` 에 날짜별로 남긴다.

| 단계 | STT | 답 찾기 | TTS | 확인할 것 |
|---|---|---|---|---|
| 1 | 없음(글로 묻기) | 고정 답 | mock | 앱 ↔ 서버 연결, 화면 흐름 |
| 2 | 폰 기본 STT | 고정 답 | mock | 한국어 인식, 가족 호칭 인식 |
| 3 | 폰 기본 STT | 고정 답 | **Qwen3-TTS Sohee** | 발음·자연스러움·속도 |
| 4 | **서버 Qwen3-ASR** | 고정 답 | Qwen3-TTS Sohee | 폰 STT 와 정확도·속도 비교 |
| 5 | 고른 STT | **기존 LLM·DB** | Qwen3-TTS Sohee | 실제 답으로 전체 흐름 |
| 6 (나중) | + VAD·문장 단위 읽기 | | | 버튼 없이 끝내기, 첫 소리까지 시간 |

## 1단계 — 연결 확인 (모델 없음)

1. 서버 ① mock 으로 실행 (`README.md`)
2. 앱 `.env` 두 주소를 모두 `http://<맥미니 IP>:8002` 로
3. 앱에서 "글로 바로 묻기" → 고정 답이 보이고 '삐' 소리가 나면 통과

## 2단계 — 폰 기본 STT

- `docs/test-sentences.md` 의 **A. 질문 문장**을 소리 내어 읽는다.
- 기록: 문장마다 맞게 받아 적었는지, 틀린 단어.
- 조용한 곳 / 시끄러운 곳 / 천천히 말하기(부모님 말투) 각각 해 본다.

## 3단계 — Qwen3-TTS (Sohee)

- 서버 ② 실행. 첫 요청은 모델을 받느라 오래 걸린다(그 시간은 기록에서 뺀다).
- `docs/test-sentences.md` 의 **B. 답 문장**을 "글로 바로 묻기" 대신 `/tts` 로 직접 넣어도 된다:
  `curl -s -X POST http://localhost:8002/tts -H 'Content-Type: application/json' -d '{"text":"...","normalize":true}'`
- 1.7B 와 0.6B 를 같은 문장으로 비교.

| 잴 것 | 방법 |
|---|---|
| 만드는 시간 | 응답의 `elapsedMs` |
| 실시간 배율(RTF) | `elapsedMs / 1000 / durationSec` — 1 보다 작아야 기다림 없이 읽을 수 있음 |
| 틀린 발음 | 문장마다 잘못 읽은 단어 수 |
| 자연스러움 | 1~5 점 (듣는 사람 2명 이상) |

## 4단계 — Qwen3-ASR (서버 STT)

- 서버 ③(8001) 과 ②(8002) 를 함께 띄우고, 앱 `.env` 의 STT 주소를 8001 로.
- 2단계와 **같은 문장**을 앱의 '서버 Qwen3-ASR' 모드로 말한다.
- 0.6B / 1.7B 비교. 글자 오류율(CER) = 틀린 글자 수 ÷ 전체 글자 수.
- 나중 전화 연결 대비: 8kHz 로 낮춘 음성도 시험한다
  `ffmpeg -i in.m4a -ar 8000 -ac 1 phone.wav` → `curl -F audio=@phone.wav http://localhost:8001/stt`

## 5단계 — 기존 LLM·DB 연결

- `server/app/answers.py` 에 실제 연결을 추가한다(키·주소는 환경변수).
- 답 글에 날짜는 "11/4" 대신 DB 날짜로 "11월 4일" 처럼 만든다(빗금 날짜는 읽기 변환이 바꾸지 않음).

## 6단계 — 나중에

- **VAD(Silero, MIT)**: 조용한 시간 0.8~1.2초에서 시작, 천천히 말하는 분은 1.5초 이상. 사용자별 설정값.
- **문장 단위 읽기**: LLM 이 스트리밍으로 답을 줄 때, 첫 문장부터 TTS. 첫 소리까지 시간을 잰다.

## 2단계 추가 시험 — 가족 돌봄 대화

서버 폴더에서 `ANSWER_PROVIDER=family-demo uv run uvicorn app.main:app --host 0.0.0.0 --port 8002`로 실행한다. 기존 개발 빌드에서 Metro를 새로고침한다. 텍스트 입력으로 답을 먼저 확인하고, iOS와 Android에서 폰 기본 STT로 같은 문장을 말한다. 자동 대화는 대화 모드를 켠다.

| # | 말할 내용 | 기대 결과 |
|---|---|---|
| C1 | 다음 주 우리 집 일정 뭐야? | 화요일 가족 식사, 토요일 장보기 |
| C2 | 소윤이 이번 주 학교 학원 일정 뭐야? | 수요일 학교 체험학습, 금요일 피아노 학원 |
| C3 | 애기 해열제 부르펜 계열 먹었는데 시간 체크해줘 | 몇 시에 먹였나요? |
| C4 | 30분 전에 먹였어 | 서버의 한국 시각에서 30분을 뺀 값을 시험 기록에 반영. 가상 일정에 등록된 다음 예정 시각 오후 9시를 안내 |
| C5 | 아니, 30분 전이 아니라 한 시간 전이야 | 같은 시험 기록의 시간을 한 시간 전으로 수정 |
| C6 | 아버지 병원 예약 언제였지? | 등록일 11월 2일, 예약일 11월 12일 목요일 오전 10시를 구분해 답변 |
| C7 | 소윤이 다음 주 학교 학원 일정 뭐야? | 이번 주 일정으로 답하지 않고 시험 범위를 안내 |

C3 → C4 → C5는 같은 앱에서 이어서 말한다. 기록은 앱 세션의 가상 값이다. 오후 9시는 시험 데이터에 미리 등록된 값이다. 텍스트의 정확한 시간은 API 자동 테스트에서 오후 4시 기준으로 확인한다.

기기별로 모델과 OS 버전을 적고, 각 턴의 **인식한 말 / 핵심 정보 일치 여부 / 화면 답변 / 들린 답변**을 남긴다. mock TTS는 재생 확인용 삐 소리가 난다. 답변 문장을 실제로 들어보려면 같은 서버에 Qwen TTS를 켜서 반복한다.
